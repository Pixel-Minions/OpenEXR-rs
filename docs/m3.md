# Milestone M3: OpenEXRCore 3.5.3 parity (2026-11-08)

The exit of the roadmap's last phase (`PLAN.md` §10): OpenEXRCore 3.5.3, with libdeflate 1.26,
zstd 1.5.7 and OpenJPH 0.32.0, ported to Rust and accepted on byte-by-byte parity with the
official `openexr==3.5.3` wheel, on Windows x86-64 and Rocky Linux 9 x86-64.

## What is ported

- **OpenEXRCore**, every file: contexts and streams, attributes, header parsing and writing,
  chunk tables, the decode and encode pipelines (unpack and pack), deep data, `exr_print_*`,
  and all 14 compressions (NONE, RLE, ZIPS, ZIP, PIZ, PXR24, B44, B44A, DWAA, DWAB, HTJ2K256,
  HTJ2K32, LJ2K, ZSTD).
- **libdeflate**: the decompressor (portable and BMI2) and the compressor at levels 0 to 12;
  Adler-32 in every form libdeflate chooses (SSE2, AVX2, AVX-VNNI, AVX-512 VNNI).
- **zstd**: the decompressor (with the fast Huffman loops and the BMI2 builds) and the
  compressor at levels 1 to 22, every strategy, the post-block splitter, long distance matching,
  index overflow correction and indices continuing from frame to frame.
- **OpenJPH**: the HTJ2K codestream, block decoders (generic, SSSE3, AVX2) and encoders
  (generic, AVX2, AVX-512), the wavelets and colour transforms in each SIMD form.
- **Every SIMD path** upstream takes, each chosen as the wheel's build chooses it on each
  platform and CPU (with D-21's two kernels taken on both platforms).

`upstream-map.toml`: 246 files `done`, 78 `n/a`, none left. The `n/a` ones are build and test
infrastructure, non-x86 CPU paths (out of scope), what Rust cannot have (`PLAN.md` O8:
allocator hooks, NULL contexts, C struct versioning), and the parts of the vendored libraries
Core never reaches (zstd's dictionaries, streaming, multithreading and superblocks;
libdeflate's gzip and CRC-32; OpenJPH's profiles and command-line parsing), each named in its
entry. Settling those as `n/a`: the owner, 2026-11-08 ("go with M3").

## How it was checked

| Check | Result |
|---|---|
| Upstream's OpenEXRCoreTest | 73 tests: 71 ported, 2 n/a (NULL contexts, C struct versioning) |
| The wheel: decode | Every layout, type, sampling, tiling and compression of `oracle/write_images.py`, upstream's test images, the openexr-images corpus and damaged copies of all of them: pixels bit for bit |
| The wheel: encode | Headers, chunk tables and chunks byte for byte, from the wheel's files and from their pixels |
| The source-built Core harness | Reads and prints of 1612 files; 5068 Core-only rewrites at every level; every half, float and uint conversion over all 2^32 inputs; zstd frames past 3.5 GB; libdeflate levels 0 to 12 |
| Platforms | `cargo xtask gate --full` on Windows (MSVC wheel) and Rocky Linux 9 (GCC wheel): 308 tests each |
| Emulated CPUs (Intel SDE) | Nehalem, Sandy Bridge, Ivy Bridge, Haswell and Skylake-SP, the wheel's checks on each, both platforms |

## Where the port differs, and why

- 21 deviations the owner approved (`docs/deviations.md`): corrected error text, writer bugs
  fixed, and D-21's kernel choice; 17 waivers name the outputs they change (`docs/waivers.md`).
  Pixels and file bytes stay bit-exact.
- 33 `I-` entries: upstream behaviour the port copies to match, bugs included
  (`docs/improvements.md`), among them three platform differences the port follows (DWA,
  OpenJPH's fused lifting, ATK shifts).
- 22 `U-` entries: undefined behaviour upstream has, which the port refuses with an error.

## Speed

On Windows, against Core built as the wheel is: the port is at or below Core's time for every
compression but HTJ2K256 and LJ2K decoding (1.06, 1.03) and ZSTD and PXR24 encoding (1.05,
1.01) (`docs/baseline.md`, "Speed"). On Linux, against GCC's build, ZSTD stays slower: encoding
about 1.2 to 1.35 times, decoding about 1.4 to 1.6 in CPU time.

## Left for later

`docs/deferred.md`: the Linux ZSTD gaps, the zeroed pipeline buffers (leaving them
uninitialized needs `unsafe`), zstd's prefetching long-offset decoder, and porting later
OpenEXR releases (`PLAN.md` §12). The next milestone (a safe Rust API, the C++ library, or
both) is the owner's to decide.
